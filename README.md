# Global Explorer

An interactive world atlas built with React 18, Vite and TypeScript. It ships a
pre-projected **Robinson** SVG atlas for a fast flat map and a canvas **3D globe**
rendered from the same source geometry. No mapping or 3D libraries are used —
everything is hand-rolled with the browser platform.

## Requirements

- Node.js 23.6 or newer (the tests import TypeScript modules using Node's
  built-in type stripping; `.nvmrc` selects Node 24)
- npm

## Getting started

```bash
npm ci
npm run dev      # http://localhost:3000
npm run build    # tsc -b && vite build
npm run check    # i18n key parity + CSS quality gate
npm test         # Node's built-in test runner
```

See [docs/PWA.md](./docs/PWA.md) for the exact steps to preview this website
in an Android Studio emulator or install its production PWA in Chrome. This
repository does not currently include a native Android/Capacitor project.

## Atlas

The atlas is generated by `scripts/build-atlas.mjs` from
[Natural Earth](https://www.naturalearthdata.com/) `ne_110m_admin_0_countries`
and written to `public/data/countries-110m.json`.

The repository ships a verified copy of that file; regenerate it with
`npm run data:atlas` when you need to change the tolerances or source.

Each shape contains:

| Field      | Type             | Description                                          |
| ---------- | ---------------- | ---------------------------------------------------- |
| `cca3`     | `string`         | ISO 3166-1 alpha-3 code (primary key)                |
| `name`     | `string`         | English country name (see *Known content gap*)       |
| `rank`     | `number`         | Natural Earth size rank; drives draw/hit order       |
| `d`        | `string`         | Robinson-projected SVG path for the flat map         |
| `rings`    | `string[]?`      | Delta/base36 encoded lon/lat rings for the 3D globe  |
| `label`    | `[lon, lat]?`    | Preferred label anchor (sphere centroid)             |
| `centroid` | `[lon, lat]?`    | Geometric centroid                                    |

`rings` and `label` are produced by `scripts/build-atlas.mjs`. The
`--globe-tolerance=<degrees>` flag overrides the geographic simplification
tolerance used when encoding `rings` (default `0.25°`); lowering it keeps more
coastline detail on the globe at the cost of atlas size, raising it shrinks the
atlas but visibly coarsens the outline.

```bash
node scripts/build-atlas.mjs --globe-tolerance=0.15
```

The atlas dimensions are `1000 × 500`. `src/hooks/useAtlas.ts` fetches the JSON
from `/data/countries-110m.json` and exposes `{ atlas, loading, error }`.

## The 3D globe

The globe is drawn from the encoded `rings` (lon/lat) rather than the SVG `d`,
so it stays geographically correct regardless of the 2D projection.

- **Basis projection.** `computeBasis(lon, lat)` builds an orthonormal frame
  (`east`, `north`, `forward`) from the camera's lon/lat. A unit-sphere point is
  projected as `x = cx + p·east · r`, `y = cy − p·north · r`, and
  `z = p·forward`. Because `z` is genuinely signed (`p·forward`), points on the
  far side (`z < 0`) are culled and rings are clipped at the horizon. It is
  **not** reconstructed with `Math.sqrt(max(0, 1 − x² − y²))`, which would always
  be non-negative and let the back face paint over the front.
- **Batched `Path2D`.** All visible rings are accumulated into a single `Path2D`
  and filled/stroked in two canvas operations, rather than one per country
  (177+). Paths are laid out biggest-first so small countries paint on top, and
  hit-testing walks the same list in reverse so small countries win over large
  neighbours.
- **Ordering.** `globeCountries()` sorts by `rank` descending. `prepared` is
  converted to unit vectors once; each frame re-projects and clips.
- **Label fit rule.** A label is only drawn when the projected country
  bounding box is at least `95%` of the text width and `fontPx × 1.1` tall, the
  anchor's depth is `> 0.3`, and **all four corners** of the text box fall
  inside the disc. Labels are placed biggest-first and any that overlap an
  already-placed label are skipped.
- **`fontPx` law.** `fontPx = max(8, min(13, base × 0.044 × (1 + 0.28 × log2(zoom))))`
  where `base` is the **unzoomed** disc radius. Geometry scales linearly with
  zoom, so the logarithmic term is what lets additional small-country names
  survive the fit rule as you zoom in.
- **Terminator.** The night side is derived from the anti-solar point
  (subsolar declination + hour angle) and shaded with a hatch pattern. The dark
  hemisphere is chosen by the sign against the sun vector, not by ring winding.
- **Interaction.** Click-vs-drag uses a `< 4px` threshold; drag rotates, wheel
  and the on-screen controls zoom, and `prefers-reduced-motion` disables the
  auto-spin. Only hovering a marker pauses auto-spin.
- **Low-power mode** caps the device pixel ratio at `1` and skips the emoji
  marker layer, but still draws the ocean, graticule, terminator and land.

## Tolerances

The atlas is a deliberately simplified representation. Two different
simplification passes are applied because the two consumers are measured in
different spaces:

| Pass                 | Space        | Tolerance | Applies to | Why                                                         |
| -------------------- | ------------ | --------- | ---------- | ----------------------------------------------------------- |
| Geographic simplify  | lon/lat (°)  | `0.25°`   | `rings`    | The globe is geographic; pixels would be meaningless.       |
| Projected simplify   | Robinson px  | `0.35 px` | `d`        | The flat map is pixel-accurate; degrees would vary by latitude. |

Additional rules:

- **Ring quantisation:** coordinates are quantised to `Q = 10` (0.1° resolution)
  before delta/base36 encoding. The same constant lives in
  `src/services/atlas.ts`; if they drift, countries land in roughly the right
  places but subtly wrong.
- **Ring encoding:** interleaved `xΔ, yΔ` integer deltas, base36 encoded,
  comma separated; the first delta is relative to `(0, 0)`.
- **Label anchors:** spherical centroid of the largest ring, rounded to 6 dp,
  and nudged inside concave shapes with a grid search so the anchor never falls
  outside its country.
- **Antimeridian handling:** rings spanning `> 180°` (but `< 350°`) are
  duplicated at `±360°` so both sides render. Rings spanning `≥ 350°`
  (Antarctica) are left unshifted so they are not duplicated against the edge.

## Country data

Country detail pages are powered by a **bundled offline dataset** so the site
works with no network and is never CORS-blocked:

- `public/data/countries.json` — ~250 territories (capital, region, subregion,
  population, area, coordinates, languages, currencies, borders, calling codes,
  map links), served from the app's own origin and fetched on demand by
  `src/services/restCountries.ts`.
- `src/data/countries.ts` — **20 hand-curated fallback records** used if the
  bundled file cannot be loaded.

The live REST Countries v5 API is opt-in. `npm run dev`/`npm run build` can use
`VITE_REST_COUNTRIES_KEY` from your ignored `.env` file. The `VITE_` prefix
means the key is exposed in browser JavaScript; only use a public/restricted
key, and use a server-side proxy for any secret production credential:

```bash
Copy-Item .env.example .env
# Add a valid public/restricted key to .env, then:
npm run dev
```

With a key configured, country pages and the directory request normalized v5
data and merge it over the bundled fallback. Successful responses are cached
in memory and local storage for 24 hours. Quota, authorization, network, and
rate-limit failures retain the bundled records and expose an explicit retry in
the country directory/details. No-key builds use the local data without a
failed API request.

To refresh the committed offline dataset, set the same variable in ignored
`.env` and run `npm run data:countries`. The script validates the response
before writing, preserves records not returned by the provider, and never
prints the key. It does not run as part of build/test, so a developer must
intentionally update the dataset.

Never commit `.env` or put the API key value in code or documentation. The
credential previously pasted into chat should be revoked/rotated if it is an
active key.

> The bundled dataset is derived from
> [`mledoze/countries`](https://github.com/mledoze/countries) (the upstream
> source REST Countries is built from), with population added from the
> [World Bank](https://data.worldbank.org/) `SP.POP.TOTL` indicator. It is
> committed as-is; regenerate it with the documented sources if you need to
> refresh it.

## Routes / sitemap

- `/` — landing page with unified place search and browse collections
- `/world` — globe + flat map
- `/directory` — searchable country directory (including countries without map geometry)
- `/landmarks` — searchable landmark collection with wonder-list filters
- `/nature` — searchable nature collection
- `/country/:cca3` — country detail
- `/landmark/:slug`, `/nature/:slug` — spot pages
- `/time-travel` — historical timeline
- `/privacy`, `/terms` — legal information
- `*` — 404 catch-all

All routes share the site navigation and footer. Content pages are loaded with
route-level code splitting. The Explorer panel remains available across routes.

`scripts/build-sitemap.mjs` emits **280 URLs** using all bundled country
records (including places without low-resolution atlas geometry), listing and
legal routes, and detail pages:

```bash
npm run sitemap -- --site=https://example.com
```

If no site is supplied it warns and writes relative `<loc>` values. For a
production deployment always pass `--site=` (or set `SITE_URL`) so the sitemap
contains absolute URLs.

## i18n

`src/i18n/{en,fr,ar}.ts` each hold **220 keys** with identical key sets;
`scripts/check-i18n.mjs` fails if they drift. Arabic is fully RTL
(`document.documentElement.dir === "rtl"`), with mirrored controls and every
`globe.*` string translated.

## Accessibility

- No `opacity` is used to de-emphasise UI; `scripts/check-css.mjs` rejects it
  (use colour, border, weight or background instead).
- The canvas globe has non-canvas equivalents: the flat map and the country
  links reach the same destinations.
- `prefers-reduced-motion` disables auto-spin, and low-power mode reduces work.

## Additive feature layer (Explorer & Time Travel)

A floating **🧭 Explorer** launcher is rendered once alongside the router
(`src/components/ExplorerLauncher.tsx`), so it appears on every page without
redesigning any existing page. It opens a drawer with a mode selector and six
panels.

### Explorer modes

🚶 Walk · 🚗 Road · ✈️ World · 🚁 Drone · 🛰️ Satellite · ⏳ History

Selecting a mode changes the discovery radius used by the nearby layers and
counts; Drone sets 2 km and Satellite sets 25 km. These modes do not display
aerial or satellite imagery. Choosing ⏳ History also enables the Time Travel layer.

### Panels

- **You Are Here** — a blue location dot with a discovery-radius circle and
  1 km counts of 🏛️ landmarks, 📜 historical events, 🍽️ dishes and 🌿 nature.
- **Explore Around Me** — six toggleable category layers (🟢 Nature,
  🔵 History, 🟠 Culture, 🟣 Food, 🔴 Discoveries, 🟡 Architecture) that update
  when the location moves.
- **Time Machine** — preset eras: 2026 / 1950 / 1800 / 1200 / Ancient.
- **Geographic Discovery** — "What was discovered here?" and "How did it change
  the world?", with an impact chain.
- **Demo suggestions** — deterministic generated examples, not AI or verified
  nearby places; Explore opens the suggested coordinates on the globe.
- **Explorer XP** — local progress counts based on countries and landmarks the
  user has opened. Other categories remain zero until real interactions exist.

Nearby stories, category counts and generated suggestions are prominently
labelled **Demo / Simulated Data**. They are not factual local listings.
Geolocation is optional and browser-permission-based; coordinates remain in
memory for the current session.

Landmarks carry explicit New Seven Wonders and Ancient Wonders tags. Current
coverage includes all seven New Seven Wonders but only the Great Pyramid entry
for the Ancient Wonders. Natural wonder entries are labelled as curated
highlights, not a complete authoritative list.

### Time Travel route

- `/time-travel` (page `src/pages/TimeTravel.tsx`) has the header
  `⏳ TIME TRAVEL`, a **Search a place** field, historical map points, and a
  draggable timeline (**1100 → 2026**) that filters the markers. Clicking a
  place opens `/country/:cca3`.

### Place extras

Country, Landmark and Nature pages gained an additive **Time Travel / Place DNA
/ Global Impact** section via `src/components/PlaceExtras.tsx`, including the
mini timeline (1100 / 1400 / 1700 / 2026), the `Historical <Place>` map panel,
the five history blocks, the `PLACE DNA` diagram (GEOGRAPHY / HISTORY / CULTURE
→ GLOBAL IMPACT), and the influence flow (PLACE → DISCOVERY/EVENT → LOCAL →
REGIONAL → GLOBAL → TODAY).

### State and data

- An opt-in **Time Travel layer** overlay on the World map
  (`src/components/TimeTravelLayer.tsx`).
- An opt-in **Near Me** layer (`src/components/NearMeLayer.tsx`): the launcher's
  "Near Me" toggle overlays a MiniMap on the World page showing nearby
  discoveries within the current discovery radius.
- State is held in `src/state/explorer.tsx` (`ExplorerProvider` / `useExplorer`)
  with `localStorage` persistence.
- New feature strings live in `src/i18n/features.ts` (en/fr/ar). They are kept
  deliberately separate from the three locale files so
  `scripts/check-i18n.mjs` is unaffected.

Geolocation is optional: it uses the browser Geolocation API when permission is
granted and otherwise falls back to a default location with preset "set a spot"
options.

> **Caveat:** all new historical/discovery content is clearly-labelled
> placeholder/mock data, structured so a real API can replace it later.

## Known content gap

**Country names are English-only.** They come from Natural Earth, which has no
localised name table, so the French and Arabic UIs display English country
names. This is documented rather than silently shipped. Other known gaps:

- Only the geometry rings are used for the globe; the `d` path includes all
  source rings, but the 110m dataset is coarse.
- Landmark and nature `type` fields are English-only.
- Landmark and nature descriptions/facts remain English-only; navigation and
  Explorer notices are translated, but the full place-data migration is not
  complete.
- The 110m dataset omits many microstates and small territories. The country
  directory links to all 250 bundled records, while the globe's accessible list
  covers only drawable atlas shapes.
- Bundled country metadata is English-only. The upstream source carries
  French/Arabic translations, but they are not bundled yet; the 20 curated
  records and the worldwide dataset both use English names.
- Bundled population values are a World Bank snapshot and may be slightly out of date.
- The invalid Svalbard/Jan Mayen area has been corrected; the worldwide data
  still has no bundled timezone arrays, so country pages now state that the
  field is unavailable rather than omitting it.
- Population is still missing for some inhabited territories and special
  regions (including Taiwan, Kosovo and Vatican City). These are not filled
  with unsourced estimates. Macau has no separate capital in the source data.
